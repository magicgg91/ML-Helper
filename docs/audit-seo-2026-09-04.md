# Audit SEO technique — ML-Helper

*Date : 2026-09-04 · Base auditée : branche `dev` @ `2958e78` (Bloc 89) · Domaine cible : https://ml-helper.com*

---

## 0. Périmètre, méthode et contexte

**Base de code.** Audit réalisé sur `dev` (à la demande du porteur de projet). La branche `main` sur GitHub contient une version très ancienne du projet (79 fichiers, historique sans ancêtre commun) et n'a pas été utilisée.

**Méthode.** Le site de production n'était pas joignable depuis l'environnement d'audit (proxy sortant). Tous les constats reposent sur :

- la lecture du code (`src/app`, `src/proxy.ts`, `src/lib/site-url.ts`, `src/app/sitemap.ts`, `src/i18n`, `messages/`, `next.config.ts`, `globals.css`) ;
- un **build de production local** (`next build`, mode standalone, identique à l'image Docker) servi sur une base seedée (seed e2e + 1 super admin + 1 guide de test) ;
- des sondes HTTP (statuts, redirections, en-têtes, négociation `Accept-Language`) ;
- l'extraction du HTML réellement servi en FR, EN et DE (balises `<head>`, `hreflang`, hiérarchie de titres, images, liens) ;
- des mesures Chromium (Playwright) desktop et mobile émulé (Moto G4, CPU ×4, Slow 4G) : TTFB, FCP, LCP, CLS, TBT, poids par type de ressource.

Google Fonts n'étant pas joignable depuis l'environnement, les mesures ont été faites avec la requête `fonts.googleapis.com` annulée immédiatement (sans cela, le premier rendu attendait ~12,7 s le timeout — voir M1).

**Ce qui est déjà en place et correct** (Blocs 42/J, 47, 60, correctifs M2/F2) : 5 langues actives (EN/FR/DE/ES/TR) avec détection `Accept-Language` ; `sitemap.xml` dynamique (18 URL, guides publiés, référentiels actifs seulement) ; description par page suivant la locale ; `noindex` sur `/login`, `/admin` et les 404 ; 404 réelles en statut 404 ; redirection 308 sur slash final ; en-têtes de sécurité (CSP nonce, X-Frame-Options, Referrer-Policy), `X-Powered-By` retiré ; `alt` présents partout ; CLS **0,000 au chargement sur toutes les pages** (conteneurs à `aspect-ratio`, tuiles à taille fixe) ; `loading="lazy"` sur toutes les images de tuiles, `eager` sur la première tuile LCP ; JS public raisonnable (146–193 Ko gzip) et éditeur admin (1 Mo) jamais chargé côté public ; ordre de tabulation clavier logique.

## 1. Priorité ÉLEVÉE

### E1 — La langue est choisie par cookie/`Accept-Language` sur une URL unique : 4 versions linguistiques sur 5 sont invisibles pour Google, et les `hreflang` émis sont invalides

- **Localisation :** `src/proxy.ts` (détection `Accept-Language` → cookie `NEXT_LOCALE`, aucune redirection), `src/i18n/request.ts` (locale lue dans le cookie), `src/lib/site-url.ts` → `languageAlternates()` (commentaire Bloc 42/J : « every hreflang alternate (including x-default) therefore points at that same URL »), `src/app/sitemap.ts`, tous les `generateMetadata`.
- **Constat (HTML servi) :**

| Requête sur `/` | `<html lang>` |
|---|---|
| sans `Accept-Language` (cas Googlebot) | `fr` |
| `Accept-Language: en-US` | `en` |
| `Accept-Language: de-DE` | `de` |
| UA Googlebot, sans en-tête | `fr` |

  Chaque page émet 6 `<link rel="alternate" hreflang>` (fr, en, de, es, tr, x-default) **qui pointent tous vers la même URL**, et le sitemap fait de même. Aucun en-tête `Vary: Accept-Language` ni `Content-Language`. Aucune balise `canonical`.
- **Impact :** Googlebot explore sans `Accept-Language` et sans cookie → il n'indexe que la version française. Les versions EN/DE/ES/TR n'ont pas d'URL, donc pas d'existence dans l'index. Des `hreflang` qui renvoient tous vers la même URL sont ignorés par Google (une annotation doit désigner une URL distincte par langue) et peuvent être signalés comme erreur dans Search Console. Le contenu qui varie selon l'en-tête sur une même URL est en outre un risque de cache intermédiaire servant la mauvaise langue (pas de `Vary`).
- **Recommandation :**
  1. Passer au routing next-intl avec préfixe de locale : arborescence `src/app/[locale]/(public)/…`, `src/i18n/routing.ts` (`locales: ['fr','en','de','es','tr']`, `defaultLocale: 'fr'`, `localePrefix: 'always'` recommandé pour des URL symétriques `/fr/tools`, `/en/tools`…). Le middleware next-intl remplace la partie locale de `src/proxy.ts` (détection puis **redirection 302** vers l'URL préfixée, cookie conservé pour la préférence ; la partie CSP/CSRF reste).
  2. `languageAlternates(path)` retourne alors `{ fr: '/fr'+path, en: '/en'+path, …, 'x-default': '/fr'+path }` et le sitemap devient valide sans autre changement ; ajouter `alternates.canonical` (URL de la locale courante).
  3. `LocaleToggle` / `use-locale-change.ts` : navigation vers l'URL équivalente (`Link` next-intl) au lieu de `POST /api/locale` + `router.refresh()`.
  4. Redirections 301 des URL actuelles non préfixées vers `/fr/…` (Googlebot les connaît déjà comme FR).
  5. Conserver la clamp admin (EN/FR) telle quelle : l'admin peut rester hors préfixe.
  
  C'est le chantier qui conditionne tout le bénéfice des 5 langues déjà traduites.

### E2 — Titres de pages trop courts, sans marque ni mot-clé « Million Lords » ; descriptions génériques ou dupliquées sur les pages à structure identique

- **Localisation :** `src/app/layout.tsx:20` (`title: "ML Helper"`, pas de `title.template`, pas de `metadataBase`), `src/lib/page-title.ts`, `generateMetadata` de `tools/[slug]` (`description: tools("subtitle")` identique pour les 4 catégories), `referentiels/[slug]` (`Public.descriptions.reference-detail` = même phrase à un mot près pour les 7 référentiels), `referentiels/page.tsx` (aucune description → hérite de l'intro de l'accueil), `guides/[slug]` (`Guides — <titre>`).
- **Constat (HTML servi, FR) :**

| URL | `<title>` (longueur) | `<meta description>` |
|---|---|---|
| `/` | `ML Helper` (9) | intro accueil (116) ✓ |
| `/tools` | `Outils` (6) | « Explore les coûts, la production… » (140) |
| `/tools/villes` · `/tools/combat` · `/tools/classement` · `/tools/competences` | `Outils — Villes` (15)… | **la même** phrase que `/tools` (×5) |
| `/referentiels` | `Référentiels` (12) | **intro de l'accueil** (héritée) |
| `/referentiels/gems` | `Gemmes` (6) | « Référentiel Gemmes pour Million Lords sur ML Helper : données vérifiées par la communauté. » (90) |
| `/referentiels/shop` | `Boutique` (8) | même gabarit, « Boutique » (92) |
| `/referentiels/combat-equipment` | `Équipements de Combat` (21) | même gabarit (105) |
| `/guides/[slug]` | `Guides — <titre>` | excerpt ✓ (ou repli générique) |
| `/legal` | `Mentions légales` (16) | « Mentions légales du site ML Helper. » (35) |

  Aucun `<title>` ne contient « Million Lords » (le seul terme réellement recherché) ; « Gems », « Shop », « Tools » (4–6 caractères) sont des titres sans contexte dans une SERP. Les 7 référentiels et les 4 pages d'outils sont indiscernables par leur description.
- **Recommandation :**
  1. `src/app/layout.tsx` : `metadataBase: new URL(siteUrl)`, `title: { default: 'ML-Helper — Outils et guides Million Lords', template: '%s | ML-Helper · Million Lords' }` (la marque et le mot-clé viennent alors automatiquement sur chaque page ; `pageTitle()` peut rester pour le détail).
  2. Une description **spécifique** par outil et par référentiel dans `messages/*.json` (`tools.meta.villes`, `references.meta.gems`, …) : 150–160 caractères qui décrivent le contenu réel (ex. gemmes : « Table complète des gemmes Million Lords : bonus par compétence et par ligue du Bronze à Légende, emplacements et coût en saphirs pour chaque fusion. »). Supprimer le gabarit `reference-detail`.
  3. `/referentiels` : ajouter une description propre (`references.description`).
  4. Titres cibles 50–60 caractères : « Gemmes Million Lords : bonus par ligue et coût en saphirs | ML-Helper ».
  5. Adapter `e2e/phase-one.spec.ts:151` (`toHaveTitle("ML Helper")`) et les tests de métadonnées existants.

### E3 — Aucune balise Open Graph / Twitter Card, aucune image de partage

- **Localisation :** aucun `openGraph`/`twitter` dans les métadonnées ; pas de `src/app/opengraph-image.*` ni d'image 1200×630 dans `public/`. Constat : `og:*` absent sur toutes les pages.
- **Impact :** pour un site communautaire dont le trafic viendra de Discord, Reddit et des groupes de joueurs, un lien partagé s'affiche sans image, avec le titre « Gemmes » et une description générique. C'est aujourd'hui le canal d'acquisition le plus probable.
- **Recommandation :** dans le layout racine `openGraph: { siteName: 'ML-Helper', type: 'website', locale, images: ['/opengraph-image.png'] }` et `twitter: { card: 'summary_large_image' }` ; une image `src/app/opengraph-image.png` (1200×630, Next génère les balises) ; sur `/guides/[slug]` `type: 'article'`, `publishedTime`, `modifiedTime`, `images: [guide.coverImage]` si présente ; sur chaque référentiel, l'illustration `referenceCatalog[].image` recadrée en 1200×630 ; `og:locale:alternate` une fois E1 fait.

### E4 — `robots.txt` absent

- **Localisation :** aucun `src/app/robots.ts` ni `public/robots.txt` ; sonde `/robots.txt` → 404 (page 404 HTML).
- **Constat :** rien n'est bloqué par erreur, mais le sitemap n'est déclaré nulle part et `/admin`, `/api`, `/login` ne sont exclus que par `noindex` (les URL restent explorées).
- **Recommandation :** `src/app/robots.ts` → `rules: [{ userAgent: '*', allow: '/', disallow: ['/admin', '/api/', '/login'] }], sitemap: absoluteUrl('/sitemap.xml')`. Vérifier en production que `NEXTAUTH_URL` vaut bien `https://ml-helper.com` : `siteUrl` en dérive, et le sitemap généré localement pointait sur `http://127.0.0.1:3000` (valeur de `NEXTAUTH_URL` de l'environnement de test) — une valeur erronée en prod produirait un sitemap inutilisable.

### E5 — Page d'accueil sans `<h1>`

- **Localisation :** `src/app/(public)/page.tsx` — l'intro est un `<p>` (commentaire « Bloc 34/D »), suivie directement de `<h2>`.
- **Constat :** hiérarchie de l'accueil = `h2 h2 h2 h2 h2 h2 h3 … h2 h3`, aucun `h1`. C'est la page qui doit porter le positionnement « outils et guides Million Lords ».
- **Recommandation :** promouvoir l'intro en `<h1>` court (« Outils et guides Million Lords ») + la phrase actuelle en `<p>`, en stylant `.home-intro h1` comme le paragraphe actuel pour ne rien changer visuellement.

## 2. Priorité MOYENNE

### M1 — Polices Google chargées par `@import` CSS : chaîne bloquante pour le premier rendu

- **Localisation :** `src/app/globals.css:1` (`@import url("https://fonts.googleapis.com/css2?family=Cinzel…&family=IBM+Plex+Sans…&family=JetBrains+Mono…")`), présent tel quel dans le CSS compilé ; CSP (`src/proxy.ts`) ouverte à `fonts.googleapis.com` / `fonts.gstatic.com` pour cette seule raison.
- **Constat :** CSS du site → feuille Google Fonts (tiers, sans `preconnect`) → fichiers de police, avant tout texte. Quand la feuille Google ne répond pas, FCP/LCP passent de ~130 ms à ~12 700 ms ; en conditions réelles, comptez +300 à +800 ms de LCP sur mobile, plus un FOUT (`display=swap`). 3 familles × 8 graisses demandées.
- **Recommandation :** `next/font/google` dans `src/app/layout.tsx` (auto-hébergement, préchargement, `size-adjust` automatique, aucune requête tierce — et un domaine de moins dans la CSP, plus simple pour le RGPD), exposé via `--font-sans/--font-serif/--font-mono` ; supprimer l'`@import` ; ne garder que les graisses utilisées.

### M2 — Images de jeu 256×256 affichées à 36–48 px : 1,4 à 3,3 Mo d'images sur les référentiels

- **Localisation :** `src/components/game-image.tsx` (`<img>` nu, pas de `srcset`), `public/equipment/**` (315 fichiers, 7,8 Mo, 196–256 px, 13–48 Ko), `public/gems/` (66 fichiers, 1,6 Mo, 256×256, 14–40 Ko), `public/templars/` (5 fichiers 1000×1353, jusqu'à 161 Ko), `public/consumables/` (41 fichiers, 2,8 Mo), `public/tools/` et `public/referentials/` (500×500, ~90 Ko). Tailles d'affichage : `.reference-equipment-image` 3 rem (48 px), `.gems-tile-image` 2,25 rem (36 px).
- **Mesures (desktop, après scroll complet) :** `/referentiels/combat-equipment` 138 images / **3 274 Ko** ; `/referentiels/gems` 61 images / **1 433 Ko** (mobile Slow 4G : `load` à 7,9 s) ; `/tools/competences` 17 images / 583 Ko ; accueil 9 images / 798 Ko. Le lazy-loading limite le coût initial (18–35 images au premier écran mobile), mais chaque scroll paie des images 5 à 7× plus grandes que nécessaire, sans `width`/`height` HTML.
- **Recommandation :** (1) générer les variantes réellement affichées (64 px et 128 px pour équipements/gemmes, 250 px pour les tuiles catégories, 300 px pour les templiers) et servir un `srcset`/`sizes`, ou passer `GameImage` sur `next/image` (le repli `onError` fonctionne aussi avec `next/image`) ; (2) ajouter `width`/`height` sur les `<img>` (ceinture et bretelles avec le CSS fixe) ; (3) pour les 180 tuiles Combat, envisager un sprite ou un chargement par famille/rareté visible. Gain attendu : −75 % de poids image sur les référentiels.

### M3 — Les images de `public/` sont servies sans cache (`max-age=0`)

- **Localisation :** `next.config.ts` (`headers()` ne pose que les en-têtes de sécurité).
- **Constat :** `/tools/cities.webp`, `/referentials/*.webp`, `/gems/*.webp`, `/equipment/**` → `Cache-Control: public, max-age=0` (revalidation à chaque visite, sur des centaines de fichiers) ; `/_next/static/*` → `immutable` (correct).
- **Recommandation :** ajouter dans `headers()` `Cache-Control: public, max-age=31536000, immutable` pour `/tools/:path*`, `/referentials/:path*`, `/gems/:path*`, `/equipment/:path*`, `/templars/:path*`, `/consumables/:path*` (fichiers nommés par convention et rarement remplacés ; en cas de remplacement, changer le nom ou accepter le cache) ; ou au reverse proxy. À combiner avec M2.

### M4 — Aucune donnée structurée (JSON-LD absent partout)

- **Recommandation (JSON-LD dans les Server Components, un composant `JsonLd` réutilisable, nonce CSP à propager comme pour le script de thème) :**
  - Accueil : `WebSite` + `Organization`/`Person` éditeur.
  - `/guides/[slug]` : `Article` (`headline`, `datePublished` = `publishedAt`, `dateModified` = `updatedAt`, `author`, `image` = `coverImage`, `inLanguage`).
  - `/tools/[slug]` : `WebApplication` (`applicationCategory: 'GameApplication'`, `operatingSystem: 'Web'`, `offers: { price: 0 }`).
  - Toutes les pages profondes : `BreadcrumbList` (Accueil › Référentiels › Gemmes), avec un fil d'Ariane visible (M7).
  - `FAQPage` seulement si un guide contient réellement une FAQ ; pas de balisage artificiel.
  - Valider avec le Rich Results Test après déploiement.

### M5 — Hiérarchie de titres : sauts de niveau et doubles `h1`

- **Constats (HTML servi) :**
  - `/tools/villes`, `/tools/competences`, `/tools/classement` : `h1` puis directement des `h3` (`city-calculators.tsx` ×6, `skills-calculators.tsx`, `ranking-calculator.tsx`) — saut h1 → h3.
  - `/referentiels/combat-equipment` : `h1` → 20 `h3` (noms de sets) → `h2` « Pouciel & Gemmes » ; `/referentiels/gems` : `h1` → `h3` ; `/referentiels` et accueil : `h2`/`h1` → `h3` sans `h2` intermédiaire pour la grille de référentiels (`reference-catalog-grid.tsx` utilise `h3`).
  - `/guides/[slug]` : le titre de page est un `h1` **et** le markdown des guides peut commencer par `# …` → deux `h1` (vérifié sur le guide de test) ; sauts possibles (`##` → `####`).
- **Recommandation :** passer en `h2` les `h3` de premier niveau des calculateurs, des sets et des tuiles gemmes ; dans `src/lib/markdown-plugins.ts`, ajouter un plugin rehype qui décale les titres du markdown d'un cran (`#` → `h2`) ou imposer `##` minimum dans l'éditeur ; rendre visibles les `h1` des outils (aujourd'hui `sr-only`, l'élément LCP est un `span` du résumé joueur).

### M6 — URL retirées sans redirection, redirection temporaire sur l'ancienne URL conservée, pas de page 404 personnalisée

- **Constats :** `/guides/referentiels/<slug>` (ancienne arborescence, présente jusqu'au Bloc 50) → **404** ; anciens slugs `gemmes`/`templiers`/`consommables` → 404 ; `/tools/referentiels` → **307** vers `/referentiels` (`redirect()` dans `tools/[slug]/page.tsx:61`) ; 404 = page générique Next (anglais, « This page could not be found »), pas de `src/app/not-found.tsx`.
- **Recommandation :** table de `redirects()` dans `next.config.ts` (`/guides/referentiels/:slug` → `/referentiels/:slug`, `gemmes` → `gems`, `templiers` → `templars`, `consommables` → `shop`, `/tools/referentiels` → `/referentiels`), toutes en **308/301** — même sans trafic indexé aujourd'hui, ces URL ont pu être partagées sur Discord. Créer `src/app/not-found.tsx` traduit avec liens Accueil / Outils / Référentiels / Guides (le `noindex` automatique est conservé).

### M7 — Maillage interne : bon depuis l'accueil, mais pas de fil d'Ariane, footer minimal, et les simulateurs n'ont pas d'URL indexable propre

- **Constat :** l'accueil lie 18 URL uniques (4 outils, 6 référentiels, guides récents, contact, légal) ✓ ; le bandeau de bascule des référentiels lie les 7 entre eux ✓ ; les liens croisés simulateur ↔ référentiel existent (`reference-tables.tsx:526,749` → `/tools/competences?open=simulator`) ✓. Manques : aucun fil d'Ariane ; footer réduit à « Mentions légales » ; les 11 simulateurs sont des onglets client dans 4 pages. Le paramètre `?open=<tab>` existe (`tools/[slug]/page.tsx:54`) mais **ne change ni le titre, ni la description, ni les `hreflang`** : `/tools/competences?open=gems` est une URL supplémentaire au contenu identique, sans `canonical` — duplication potentielle, et impossibilité de se positionner sur « calculateur gemmes Million Lords ».
- **Recommandation :** (1) faire varier `generateMetadata` selon `searchParams.open` (titre/description du simulateur) et poser `alternates.canonical` — ou mieux, des sous-routes `/tools/competences/gems` ; (2) fil d'Ariane visible + `BreadcrumbList` (M4) ; (3) footer avec Outils / Référentiels / Guides / Contact ; (4) inclure les URL de simulateurs dans le sitemap une fois distinctes.

### M8 — Contrastes insuffisants sur les textes atténués

- **Localisation :** `src/app/globals.css` — `--text-faint` (`#5c6472` sombre, `#858b95` clair), 11 usages dont `.category-btn-unavailable .category-btn-label` (« Bientôt disponible », mention explicitement voulue visible au Bloc I), `.total-box small`, `.level-up-chest-empty`, `.login-card small`, `.sk-breakdown` ; `--accent` violet `#8b6bb8` utilisé en couleur de texte (hover, `aria-current`) ; `--gold` clair `#9b6f1e`.
- **Mesures (WCAG AA texte normal ≥ 4,5:1) :**

| Token | Fond | Ratio |
|---|---|---|
| `--text-faint` sombre | `#1b2029` / panneau | 2,74 / 2,48 ✗ |
| `--text-faint` clair | `#e4e7eb` / panneau | 2,76 / 3,06 ✗ |
| `--accent` (violet) sombre en texte | `#1b2029` | 3,81 ✗ |
| `--gold` clair | `#e4e7eb` | 3,61 ✗ |
| `--text-dim` clair | `#e4e7eb` | 4,45 (limite) |
| `--text`, `--text-dim` sombre, `--violet-bright` | — | 5,7 à 12,9 ✓ |

- **Recommandation :** `--text-faint` ≥ `#8a919d` (sombre) et ≤ `#6b7280` (clair) ; `--accent-strong` (7,2–8:1) pour tout texte coloré ; `--text-dim` clair → `#5b6270`. Verrouiller par un test axe (F4).

### M9 — Toutes les pages sont rendues à chaque requête, sans cache HTML

- **Localisation :** `connection()` + `cookies()` (via next-intl) dans toutes les pages ; build : 100 % des routes `ƒ (Dynamic)` ; `Cache-Control: private, no-cache, no-store`.
- **Constat :** TTFB local 20–70 ms (SQLite et Node sur la même machine) ; en production s'ajoutent latence serveur et reverse proxy. Aucun problème d'indexation, mais chaque visite (Googlebot compris) relance requêtes Prisma + rendu ; le layout public interroge en plus la table des guides à chaque page pour la recherche.
- **Recommandation :** une fois E1 fait (locale dans l'URL, plus de `cookies()` sur le public), activer `revalidate = 300` ou `'use cache'`/`cacheLife` sur les pages publiques avec `revalidatePath()` déclenché par les routes admin de mutation ; à défaut, cache court (60 s) au reverse proxy.

## 3. Priorité FAIBLE

- **F1 — Pas de manifeste PWA ni d'icônes mobiles.** Aucun `manifest`, `apple-touch-icon`, `theme-color`, ni icônes 192/512 (seul `src/app/favicon.ico`, 256×256). Ajouter `src/app/manifest.ts` (`name`, `short_name: 'ML-Helper'`, `display: 'standalone'`, `theme_color`, `background_color`, icônes PNG) + `src/app/icon.png` / `apple-icon.png`. Utile pour « Ajouter à l'écran d'accueil » côté joueurs mobiles ; pas un facteur de classement.
- **F2 — Référentiel inactif accessible en 200.** `/referentiels/events` (Bloc 60, inactif par défaut) répond 200 avec un `h1` et un état vide : il est bien exclu du sitemap et de la recherche, mais reste indexable s'il est lié ou deviné. Poser `robots: { index: false }` dans `generateMetadata` quand `!active[reference.calculatorSlug]`, ou `notFound()`.
- **F3 — Résidus du scaffold dans `public/`** : `next.svg`, `vercel.svg`, `globe.svg`, `window.svg`, `file.svg` sont inutilisés — à supprimer.
- **F4 — Aucun test automatisé d'accessibilité ni de métadonnées de bout en bout.** Ajouter `@axe-core/playwright` sur `/`, `/tools/competences`, `/referentiels/combat-equipment` et un test e2e vérifiant `title`, `description`, `canonical`, `hreflang` (URL distinctes), JSON-LD et `og:image`.
- **F5 — Onglets ARIA sans navigation par flèches.** `role="tablist"/"tab"` sur des `<button>` (`skills-calculators.tsx`, `combat-calculators.tsx`, `city-calculators.tsx`, `reference-tables.tsx`) : Tab/Entrée fonctionnent (vérifié), mais le pattern WAI-ARIA attend ←/→ et `aria-controls`/`tabpanel`. Le nouveau sélecteur de langue (Bloc 48/C) implémente correctement le pattern listbox — s'en inspirer.
- **F6 — Préchargement agressif.** L'accueil déclenche ~33 requêtes de prefetch RSC (toutes les cartes sont des `Link`). `prefetch={false}` sur les grilles de tuiles réduirait le bruit réseau sur mobile ; sans effet SEO.
- **F7 — Préparation AdSense** (pas encore d'usage) : mise en page saine (pas de pop-up, texte lisible, mobile OK). Le jour venu : réserver des conteneurs de taille fixe (`min-height`) pour éviter le CLS des annonces ; limiter aux pages guides/référentiels (les simulateurs sont trop interactifs) ; prévoir une CMP/consentement cookies conforme UE (mettre à jour la section « Cookies » de `/legal`) ; ouvrir la CSP aux domaines Google Ads (`script-src`, `frame-src`, `img-src`, `connect-src`) — la CSP nonce actuelle bloquerait AdSense telle quelle ; rester au-dessus des seuils CWV, d'où l'intérêt de M1–M3.
- **F8 — Vérifier `NEXTAUTH_URL` en production** (voir E4) : `siteUrl`, le sitemap et les `hreflang` en dérivent tous ; toute divergence (`http://`, port, sous-domaine) casse ces trois signaux d'un coup. Envisager une variable dédiée `SITE_URL` avec `https://ml-helper.com` en dur par défaut.

## 6. Résumé exécutif

Le socle technique est sain : statuts HTTP corrects, 404 réelles, sitemap dynamique, `noindex` là où il faut, en-têtes de sécurité, CLS nul, JS public léger, accessibilité des images et du clavier correcte. Mais le site reste **presque invisible pour les moteurs et pour le partage social** : la langue est portée par un cookie sur une URL unique, donc seule la version française existe pour Google et les 6 `hreflang` par page sont invalides ; les titres font 4 à 21 caractères sans « Million Lords » et les descriptions des 7 référentiels et des 4 outils sont des copies d'un même gabarit ; il n'y a ni Open Graph, ni image de partage, ni `robots.txt`, ni données structurées. Côté performance, l'application est rapide mais les images de jeu (256 px affichées à 36–48 px, 1,4 à 3,3 Mo par référentiel) et l'`@import` Google Fonts sont les deux risques pour les Core Web Vitals.

**Les 3 actions à plus fort impact, dans l'ordre :**
1. **E1 — URL par langue (`/fr/…`, `/en/…`, `/de/…`, `/es/…`, `/tr/…`) avec `hreflang` réels + `canonical`** via le routing next-intl. C'est ce qui rend enfin utiles les 4 traductions déjà livrées.
2. **E2 + E3 — Métadonnées par page** : gabarit de titre avec la marque et « Million Lords », descriptions spécifiques par outil/référentiel, Open Graph + image 1200×630. Effort faible, effet immédiat sur le CTR et sur chaque lien partagé sur Discord.
3. **M2 + M3 + M1 — Images redimensionnées avec `srcset` et cache immutable, polices via `next/font`** : −75 % de poids image sur les référentiels et suppression de la seule chaîne bloquante tierce, pour sécuriser LCP en production et préparer AdSense.

Puis, en seconde vague : `robots.ts` (E4), `h1` sur l'accueil (E5), redirections 301 des anciennes URL et page 404 (M6), JSON-LD et fil d'Ariane (M4/M7), contrastes (M8), métadonnées par simulateur (`?open=`) (M7).
